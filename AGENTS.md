# AGENTS.md

Внутренний инструмент кафедры: расчёт штатных ставок ординатуры КГМА (2026–2027). Одностраничное
приложение, все данные живут в браузере (localStorage), Excel — единственный источник и приёмник данных.
UI целиком на русском.

## Стек и команды

| Слой | Что используется |
|---|---|
| UI | React 19 (`StrictMode`), хуки, никакого роутера |
| Сборка | Vite 7 + `@vitejs/plugin-react` |
| Стили | Tailwind CSS 4 через `@tailwindcss/vite`; **нет `tailwind.config`** — тема в `@theme` внутри `src/style.css` |
| Примитивы | Zag.js 1.44: `dialog`, `file-upload`, `select`, `tabs`, `toast`, `combobox` + `@zag-js/react` |

| Пакеты | pnpm 11 (`packageManager: pnpm@11.9.0`) |
| Тесты/линт | отсутствуют (нет vitest/jest/eslint/prettier, нет CI) |

```bash
pnpm dev      # vite --host 127.0.0.1 (порт 5173, при занятости — следующий)
pnpm build    # vite build → dist/
pnpm preview  # предпросмотр сборки
./start.command   # dev + открыть браузер
```

`pnpm-workspace.yaml` содержит только `allowBuilds: esbuild`.

## Данные

Три независимых набора в localStorage (ключи экспортируются из `domain.js`):

| Ключ | Содержимое |
|---|---|
| `kgma-staff-allocations-v1` | ординаторы |
| `kgma-pps-allocations-v1` | сотрудники ППС и их ставки |
| `kgma-specialty-report-v1` | импортированный отчёт «По специальности» |

```js
// ординатор
{ id, name, position, degree, department, program: 'Общее', studyYear, funding, rate, phone, employment, workplace, specialty }
// funding: 'budget' | 'contract' | 'cis'  → FUNDING = { budget: 'Бюджет', contract: 'Контракт', cis: 'СНГ' }
// ППС
{ id, name, position, department, budgetRate, contractRate, totalRate }
// position хранится полным («Доцент», «Ассистент»), department — из шапки выписки кафедры
// отчёт по специальностям
{ faculty, specialty, passedBudget, passedContract, passedCis, passedForeign, passedTotal,
  appliedBudget, appliedContract, appliedCis, appliedForeign, appliedTotal }
```

`row.rate` у ординатора — наследие: импорт пишет `0`, диалог даёт ввести 0…5 с шагом 0.05,
но **в расчётах поле не участвует** (ставка везде считается как человек ÷ 4).

Чтение — `loadRows/loadPpsRows/loadSpecialtyRows` (терпимо к битому JSON → `[]`), запись — `save*`.
Пишутся только при импорте, сохранении/удалении через диалог и очистке. Состояние фильтров не персистится.

## Домен и расчёты

- **Ставка = человек / 4.** Зашито в двух местах: `totals()` (`budgetRate`, `contractRate`) и формулы
  экспорта (`B9/4`, `B10/4`). Делитель 4 — решение кафедры, а не константа из данных.
- **`uniquePeople(rows)`** считает уникальные пары `фио|год обучения` (регистр не важен). Поэтому:
  «общий итог» — уникальные люди, «бюджет»/«контракт» — уникальные люди с этим источником.
  **СНГ ни в одну из карточек не попадает**, отсюда при наличии СНГ-строк общий итог ≠ бюджет + контракт.
- `clean()` схлопывает любые пробелы в один (в т.ч. `\r\n` в телефонах), `numeric()` парсит `1,5` и
  выкидывает мусор, `fmtRate()` печатает ru-RU максимум с 2 знаками, `uid()` — `crypto.randomUUID`.
- **Импорт ординаторов** — `parseStudentSheet(sheet, fileName, sheetName)`:
  - строка заголовков — первая, где есть `^(фио|фамилия,? имя)`; колонки ищутся по regex:
    `должност`, `кафедр`, `телефон`, `специальност`, `^б$|^бюджет$`, `^к$|^контракт$`, `снг`;
  - фактический файл кафедры: `ФИО | контракт за год | за полугодие | оплата | Б | К | СНГ | кафедра | телефон | Специальность | …`;
  - **год обучения берётся не из таблицы**, а из имени файла / имени листа / первых 5 строк:
    `/(?:^|\D)2\s*[-–—]?\s*(?:год|гол|курс)/` → `2 год`, аналогично `1 год`, иначе `Не определён`
    (в `гол` — опечатка реальных файлов, поддерживается намеренно);
  - строка принимается только если имя ≥ 5 символов, содержит пробел и не является числом, есть кафедра
    и специальность; строки `Итого`/`Ставки` отбрасываются;
  - встретив ячейку `ушёл`/`ушел`, парсер перестаёт принимать строки до конца листа;
  - источник: первая ненулевая из Б → budget, СНГ → cis, К → contract; по умолчанию `contract`.
- **`mergeStudentRows(existing, imported)`** — ключ `name|department|specialty|funding|studyYear`.
  Существующие строки с годом `Не определён` вытесняются пришедшими с тем же
  `name|department|specialty|funding`, поэтому повторный импорт с уточнённым годом не плодит дубли.
  Возвращает `{ rows, added, updated }` — это и показывается в тосте.
- **Импорт ППС** — `parsePpsSheet`: ищет строку `Ординатура`, шапку с `ФИО`+`должност`, строку `Бюджет`;
  бюджетная ставка — колонка блока «Ординатура», контракт — сумма колонок до «Интернатура»;
  строки с нулевой суммой отбрасываются, разбор идёт до строки `Итого`. Кафедра берётся из шапки выписки
  (`/кафедр[аы]?\s*[:\-–]\s*(.+)/i`, реально — «Кафедра: Хирургии общей практики»), должность проходит
  через `fullPosition()`. Импорт ППС **заменяет** данные, а не дополняет (одна выписка — одна кафедра).
- **`fullPosition(value)`** — словарь сокращений из выписок кафедр: `доц`→`Доцент`, `асс`→`Ассистент`,
  `проф`→`Профессор`, `зав.каф.`→`Заведующий кафедрой`, `и.о.зав.каф.`→`И.о. заведующего кафедрой`,
  `и.о.доцента`, `ст.преп`→`Старший преподаватель`, `завуч`→`Заведующий учебной частью`,
  `лаборант`/`старший лаборант`. Значения через запятую нормализуются по частям («и.о.зав.каф., доцент» →
  «И.о. заведующего кафедрой, доцент»), незнакомое значение возвращается как есть. Применяется и при
  импорте, и при чтении из localStorage (`loadPpsRows`), поэтому старые сокращения в браузере тоже
  становятся полными.
- **Импорт отчёта по специальностям** — `parseSpecialtySheet`: нужен маркер `прием документов фпмо`,
  разбор начинается после строки `Итого интернатура:`; строка без номера и с нулями задаёт факультет,
  разбор заканчивается на `Всего:`. Приоритет: если отчёт импортирован — в экспорт идёт он,
  иначе агрегаты по `кафедра+специальность`.
- **`exportExcel({ rows, specialtyRows, department, year })`** — три листа:
  `Список` (с автофильтром, сортировка кафедра → ФИО), `Расчет ставок` (фильтры кафедры/года, итоги,
  формулы деления на 4), `По специальности`. Файл: `Штатное_расписание_2026-2027_<ISO-дата>.xlsx`.
  Возвращает `false`, если экспортировать нечего (кнопка показывает предупреждение).

## Состояние и фильтры

Цепочка вычислений в `App.jsx` (всё на `useMemo`, реактивно):

```
rows ──поиск+кафедра+год──► scopedRows ──источник──► visibleRows ──► таблица
                                             └────► summary = totals(visibleRows) ──► карточки
```

- `departmentOptions` — «Все кафедры» (`value: 'all'`) + кафедры, отсортированные `localeCompare('ru')`,
  каждая с подсказкой `hint` из `totals()`: `N чел. · M ст.`.
- Значение `'all'` — маркер «без фильтра» у всех трёх селектов; `resetValue="all"` в `SearchSelect`.
- После импорта Excel фильтры сбрасываются, тост сообщает `Добавлено/Обновлено`.
- Кнопка «Выгрузить Excel» экспортирует `scopedRows` (кафедра+год) — **фильтр «Источник» в файл не попадает**.
- «Очистить всё» удаляет оба ключа ординаторов и отчёта, «Очистить ППС»/«Очистить отчёт» — свои.

**PpsView** (второй этап) устроен так же, но набор фильтров другой, потому что в выписке ППС нет года:

`rows → (поиск по ФИО/должности + кафедра + должность) → scopedRows → (источник) → visibleRows`

- «Источник» здесь означает ставку: `Бюджет` → `budgetRate > 0`, `Контракт / ИГ` → `contractRate > 0`.
- `positionOptions` собираются по `position` с подсказкой `N чел. · M ст.` из `ppsTotals()`.
- Карточки (`ppsTotals`), таблица «Ставки по должностям» (`ppsGroups`) и список сотрудников считаются
  по `visibleRows`; импортированная кафедра выводится подзаголовком в шапке экрана.
- Фильтра «год» нет: ППС-выписка не содержит года обучения, а «кафедра» обычно одна — импорт заменяет
  данные целиком (если в хранилище окажутся строки разных кафедр, фильтр заработает сам).

## UI-конвенции

- Палитра: фон `stone-100`, акцент `emerald-950`/`amber-400`, текст `slate-*`. Заголовки — `font-serif` (Prata),
  остальное — Manrope (`@theme` в `style.css`).
- Карточка: `rounded-2xl border border-stone-200 bg-white p-5 shadow-sm`, акцент сверху
  `border-t-[3px] border-t-emerald-600` (бюджет) / `border-t-amber-400` (контракт).
- Единый блок статистики: `statLabelClass` / `statValueClass` / `statHintClass` и компонент `Stat`
  (подпись 11 px капс → значение `text-4xl` → пояснение 11 px). Карточки «Бюджет»/«Контракт» — это два
  `Stat` в `grid-cols-2`, разделённые `border-l`, поэтому все три карточки выровнены построчно.
- Кнопки: `buttonClass` / `dangerButtonClass`, главное действие — амбер-кнопка, импорт — `ExcelUpload`.
- Таблица: шапка `sticky top-0 z-10`, ячейки `tableCellClass`. Обязательные тонкости:
  - `min-w-[min(1080px,100%)]` — таблица не вылезает за карточку, но не сжимается уже 1080 px;
  - колонка «Год» — `min-w-28 whitespace-nowrap` (иначе «1 год» рвётся на две строки);
  - колонка «Телефон» — `w-[1%]` + `<span class="block max-w-18 truncate" title={phone}>`: в реальных
    данных бывают три номера через `/` (`0775662550/0703707520/…`), из-за них колонка растягивала таблицу;
  - колонка действий — `w-[1%]`, кнопки `size-8 grid place-items-center`, иконки — SVG `viewBox="0 0 20 20"`.
- Иконки: `Chevron` (20 px) и иконки действий (16 px) на одной сетке 20×20, поворот через класс
  `rotate-180` + `origin-center` (крутятся вокруг своего центра, не «уезжают» как текстовый `⌄`).

## Zag.js: как это подключено и на что наступали

- Общий шаблон: `useMachine(machine, {…})` → `connect(service, normalizeProps)` → разметка из
  `api.get*Props()`. Состояния стилизуются data-атрибутами: `data-[highlighted]:…`, `data-[state=checked]:…`.
- **z-index попапа.** Popper пишет `--z-index` на позиционер, беря его из computed `z-index` **контента**.
  Поэтому `z-[80]` ставится на `getContentProps()`, а не на `getPositionerProps()`: иначе позиционер
  остаётся `auto` и «липкая» шапка таблицы (`z-10`) рисуется поверх списка.
- **SearchSelect** (`@zag-js/combobox`):
  - триггер — обычная кнопка со значением (`w-60`, длинное имя обрезается, полное — в `title`), поиск
    живёт в шапке попапа: `useLayoutEffect` фокусирует его при открытии (с `useEffect` быстрый «клик + набор»
    терял первый символ);
  - `selectionBehavior: 'clear'` — выбранное значение не подставляется в поиск (иначе поле фильтровало само себя);
  - `inputBehavior: 'autohighlight'`, `allowCustomValue: false`, `closeOnSelect: true`;
  - поиск регистро- и «ё»-независимый (`fold`), совпадения подсвечиваются `<mark>`;
  - `onOpenChange` очищает запрос только при закрытии — при открытии набором текста запрос нужно сохранить;
  - `positioning: { placement: 'bottom-start', sameWidth: false }`: у машины комбобокса `sameWidth` по
    умолчанию `true`, тогда позиционер получает ширину триггера, сдвиг у края окна не срабатывает и широкий
    список уезжает за экран (ловится в ППС, где пикер стоит третьим от правого края);
  - **`closed.focused` в машине обрабатывает `INPUT.CHANGE`**, а переход `closed.idle → closed.focused`
  делает обработчик `onFocus`. Если перекрыть `onFocus` своим, набор текста в закрытое поле перестаёт
  открывать список; поэтому свой код вызывается в цепочке (`inputProps.onFocus?.(event)`).
- **ZagSelect** — обычный select для «Год»/«Источник» и для полей «Год обучения», «Источник
  финансирования», «Тип занятости» в `PersonDialog` (`compact` — без подписи). Поле «Кафедра» в диалоге —
  свободный текст (`Field`), а не пикер: значения фильтра и записи при этом сравниваются строкой.
- z-шкала приложения: шапка таблицы `z-10` → фон диалога `z-50` → содержимое диалога `z-[60]` →
  попап select/combobox `z-[80]` → тосты `z-[100]`. Для `select` это правило в `style.css`
  (`[data-scope="select"][data-part="positioner"] { z-index: 80 !important }`), для комбобокса — класс
  на контенте (см. ниже, почему именно на нём).
- Диалоги (`PersonDialog`, `ConfirmDialog`) монтируются только при `open` и рисуются через `Portal`;
  `ConfirmDialog` — `role: 'alertdialog'`.
- `ExcelUpload` принимает до 20 файлов, сам очищает очередь после `onFiles`; подпись очереди —
  `signature` из `name:size:lastModified`, чтобы не перезапускать импорт на каждый рендер.

## Известные особенности и долги

- СНГ не отражён в карточках: «Общий итог» включает СНГ, а «Бюджет»/«Контракт» — нет.
- Экспорт не учитывает фильтр «Источник» (идёт по кафедре+году).
- Год обучения определяется по имени файла — при импорте другого файла год может стать
  `Не определён`; лечится повторным импортом (см. `mergeStudentRows`).
- Нет ни тестов, ни линтера; `eslint-disable`-комментарии стоят намеренно для эффектов по подписи.

## Правила правок

- Сообщения коммитов — английские, императив, тело объясняет «зачем»; текст интерфейса — русский.
- Версии `@zag-js/*` держим в 1.44.x: API машин между минорами меняется (например, части
  `getListProps`/`getTriggerProps` и поведение `closed.focused`).
- Новые зависимости — только при явной необходимости; `xlsx` и zag уже закрывают весь функционал.
- Правку UI подтверждать запуском приложения (см. «Проверка изменений»): статический просмотр не
  ловит ни растяжение таблицы, ни перекрытие попапа, ни потерю символов при вводе.
